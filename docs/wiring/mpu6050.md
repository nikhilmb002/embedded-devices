# Wiring: MPU6050 + Raspberry Pi Pico 2 (I²C)

The MPU6050 uses the Pico's primary I²C bus. These connections also let the
MPU6050 share that bus with the SSD1306 display.

| MPU6050 module pin | Pico 2 connection | Notes |
|---|---|---|
| VCC | 3V3(OUT), pin 36 | Use 3.3 V logic on SDA/SCL. Check the breakout's own power requirements. |
| GND | GND, pin 38 | Share ground with the display and Pico. |
| SDA / SDI | GP4, pin 6 | Primary I²C data. |
| SCL / SCLK | GP5, pin 7 | Primary I²C clock. |
| AD0 | GND | Selects I²C address `0x68`; connect to 3V3 for `0x69`. Do not leave it floating. |
| INT | Not connected | Optional; the driver can configure interrupts, but polling needs no INT wire. |
| XDA | Not connected | Auxiliary I²C data for a sensor connected to the MPU's internal auxiliary bus. |
| XCL | Not connected | Auxiliary I²C clock for a sensor connected to the MPU's internal auxiliary bus. |

`XDA` and `XCL` are not the Pico's main SDA/SCL pins. Leave them open unless
you are connecting a second sensor to the MPU6050's auxiliary I²C bus. In that
case, connect the second sensor's SDA to XDA, SCL to XCL, and share its ground;
configure the MPU's auxiliary I²C master in software.

The library uses `i2c0`, GP4/GP5, and 400 kHz in the Pico example. The sensor
address is `0x68` with AD0 low and `0x69` with AD0 high. `WHO_AM_I` identifies
the chip separately: `0x68` for MPU6050 and `0x70` for MPU6500. The current
driver accepts both for the shared motion sample path.

Keep all I²C pull-ups at 3.3 V. Breakout boards differ: some include pull-ups
and a regulator, while bare sensors need an appropriate supply and external
pull-ups. The Pico and all modules must share a common ground.

Optional debug UART: FT232RL RX to Pico GP0 (pin 1), TX to GP1 (pin 2), and GND
to a Pico GND pin. Use 3.3 V logic and 115200 baud.
