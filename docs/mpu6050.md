# MPU6050 / MPU6500 driver

The portable driver accepts MPU6050 (`WHO_AM_I=0x68`) and MPU6500
(`WHO_AM_I=0x70`) devices and uses `edev_i2c_bus_t`, so it works with the Pico
hardware I2C backend or any backend implementing the common bus operations.
The MPU6050 address is `0x68` when AD0 is low and `0x69` when AD0 is high.

```c
static edev_i2c_bus_t bus;
static mpu6050_t imu;

edev_pico_i2c_init(&bus, i2c0, 4, 5, 400000);
int r = mpu6050_init(&imu, &bus, MPU6050_ADDR_AD0_LOW);
if (r == EDEV_OK) {
    mpu6050_sample_t sample;
    r = mpu6050_read(&imu, &sample);
    /* sample acceleration is in g, temperature in °C, gyro in °/s */
}
```

Initialization checks `WHO_AM_I`, selects the X gyro clock, wakes the sensor,
and starts with ±2 g and ±250 °/s ranges. Select other full-scale ranges with
`mpu6050_set_accel_range` and `mpu6050_set_gyro_range`; `mpu6050_read_raw`
returns the signed 16-bit ADC values. The scaled API converts them using the
currently selected ranges.

The live acceleration, gyro, and temperature path is shared by both devices.
The extended FIFO, auxiliary-I2C, and DMP controls are exposed for MPU6050;
their behavior on MPU6500 has not been validated by this project.

The public API also exposes sample rate and low-pass filter configuration,
power management, self-test factory codes, offset registers, interrupt status,
FIFO source/enable/reset/count/read operations, and generic register access.
Auxiliary I2C slave registers can be programmed through generic register
access; helper functions enable the internal master and select its clock.

## DMP firmware

No DMP firmware is bundled. Supply an image no larger than 2048 bytes to
`mpu6050_dmp_upload`, then use the DMP enable and FIFO APIs to control it. The
image's packet layout and initialization requirements are firmware-specific;
the driver does not decode a universal DMP packet format.

## Hardware verification

`/mnt/c/pico/i2c_learn` is the Pico 2 consumer project used for hardware checks.
It uses `i2c0`, GP4/GP5, 400 kHz, and UART output. Connect the sensor to the same
bus, set AD0 to match the configured address, and build/flash the project. The
application displays scaled accel/gyro/temperature values on the SSD1306 and
prints values and I2C errors over UART.
